Obiettivo e architettura

Il progetto stima un target numerico tramite un albero di regressione. Il repository espone due modalità autonome: condividono i concetti di dominio, ma non comunicano tra loro.

MODALITÀ A

GUI locale Swing

  • Input da training set .dat.
  • Attributi esplicativi discreti; target continuo.
  • Training in memoria e visualizzazione dell’albero.
  • Statistiche, zoom, centratura e dettagli testuali.
nessun databasenessuna rete
MODALITÀ B

JAR client/server

  • Input da tabella MySQL/MariaDB.
  • Attributi discreti e continui; target continuo.
  • Training o caricamento di un archivio serializzato.
  • Predizione interattiva dal client testuale.

Algoritmo e modello software

Criterio di apprendimento

Ogni nodo copre una partizione di esempi. L’errore memorizzato come variance è, in realtà, la somma degli errori quadratici (SSE) rispetto alla media del target.

ŷS = (1 / |S|) · Σi∈S yi
SSE(S) = Σi∈S (yi − ŷS)²

Per ogni attributo candidato si costruiscono le partizioni e si sceglie lo split che minimizza Σ SSE(figlio). Una foglia restituisce la media ŷ della propria partizione.

01 · INPUT
Carica dati
Schema, feature e target.
02 · CANDIDATI
Prova gli split
Uno per attributo valido.
03 · SCELTA
Minimizza SSE
Somma degli errori dei figli.
04 · RICORSIONE
Genera figli
Ripete sulla partizione.
05 · OUTPUT
Crea foglia
Predizione = media target.

Arresto

La soglia è il 10% del training set, con divisione intera. Il nodo diventa foglia quando la partizione non supera la soglia oppure quando non produce più di un ramo valido.

Differenza tra le modalità

Il codice locale valuta split discreti. Il server distribuito include anche ContinuousNode e scarta feature continue senza valori distinti.

03

Interfaccia grafica

L’estensione Swing rende leggibile la struttura appresa senza introdurre dipendenze esterne. Il training parte da un file locale e il risultato viene disegnato su un canvas navigabile.

Flusso utente

  1. Inserimento o selezione del file .dat.
  2. Parsing e validazione tramite Data.
  3. Costruzione di RegressionTree.
  4. Conversione in VisualTree e rendering.

Rendering

  • layout ricorsivo basato sulla larghezza dei sotto-alberi;
  • zoom limitato al 50–150% e centratura della radice;
  • scroll per alberi più grandi del viewport;
  • conteggio di nodi, foglie, profondità e tempo.
Threading. Finestra e azioni sono create sull’Event Dispatch Thread di Swing.

Concorrenza e sessione

MultiServer accetta connessioni in ciclo. Per ogni socket crea un ServerOneClient, sottoclasse di Thread, che conserva training set, albero e nome archivio della sessione.

Persistenza

Dopo il training il server serializza automaticamente l’albero in un file con il nome della tabella. Un’esecuzione successiva può caricarlo senza interrogare il database.

Esecuzione, limiti e conclusioni

Avvio rapido

GUI locale
mkdir -p build/gui
javac -d build/gui \
  src/data/*.java src/tree/*.java \
  src/utility/*.java estensioni/*.java
java -cp build/gui estensioni.RegressionTreeGUI

Avviare dalla radice per usare direttamente prova.dat.

Client/server
mysql -u root -p \
  < distribution/server/sql_file/map6_setup.sql
cd distribution/server
java -jar mapServer.jar 8080
# secondo terminale, dalla radice:
java -jar distribution/client/mapClient.jar \
  localhost 8080

Il Connector/J deve restare accanto a mapServer.jar.

Limiti tecnici e mitigazioni

Separazione funzionale
GUI solo locale; predizione solo client/server. Mitigazione: presentare le due modalità come strumenti distinti.
Sicurezza di rete
Protocollo senza TLS o autenticazione. Mitigazione: uso esclusivo su rete locale o fidata.
Configurazione fissa
Database e credenziali sono incorporati. Mitigazione: centralizzare la configurazione in variabili d’ambiente o file esterno.
Serializzazione Java
Archivi sensibili alla versione e non adatti a input non fidati. Mitigazione: validare i percorsi e usare un formato esplicito.
Training sincrono nella GUI
Dataset grandi possono bloccare l’EDT. Mitigazione: spostare il training in uno SwingWorker.
Riproducibilità server
Nel repository analizzato il client/server è disponibile solo come JAR; il relativo sorgente non è presente. Mitigazione: versionare anche i sorgenti della build distribuita.

Valutazione finale

Esito. L’implementazione separa correttamente dominio, visualizzazione e distribuzione. L’algoritmo è verificabile, la GUI rende l’albero comprensibile e il server supporta più client, persistenza e predizione. Le priorità successive sono test end-to-end, configurazione esterna e training asincrono.
